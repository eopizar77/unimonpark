Definición de métodos de consulta
El proxy del repositorio tiene dos formas de derivar una consulta específica de la tienda a partir del nombre del método:

Al derivar la consulta directamente del nombre del método.

Mediante el uso de una consulta definida manualmente.

Las opciones disponibles dependen de la tienda en cuestión. Sin embargo, debe existir una estrategia que determine qué consulta se genera. La siguiente sección describe las opciones disponibles.

Estrategias de búsqueda de consultas
Las siguientes estrategias están disponibles para que la infraestructura del repositorio resuelva la consulta. Con la configuración XML, puede configurar la estrategia en el espacio de nombres mediante el query-lookup-strategyatributo. Para la configuración Java, puede usar el queryLookupStrategyatributo de la EnableJpaRepositoriesanotación. Es posible que algunas estrategias no sean compatibles con determinados almacenes de datos.

CREATEIntenta construir una consulta específica de la tienda a partir del nombre del método de consulta. El enfoque general consiste en eliminar un conjunto dado de prefijos conocidos del nombre del método y analizar el resto del método. Puede leer más sobre la construcción de consultas en “ Creación de consultas ”.

USE_DECLARED_QUERYIntenta encontrar una consulta declarada y lanza una excepción si no la encuentra. La consulta puede definirse mediante una anotación o declararse por otros medios. Consulte la documentación del almacén específico para conocer las opciones disponibles. Si la infraestructura del repositorio no encuentra una consulta declarada para el método durante el arranque, falla.

CREATE_IF_NOT_FOUND(Por defecto) combina CREATEy USE_DECLARED_QUERY. Primero busca una consulta declarada y, si no encuentra ninguna, crea una consulta personalizada basada en el nombre del método. Esta es la estrategia de búsqueda predeterminada y, por lo tanto, se utiliza si no se configura nada explícitamente. Permite definir consultas rápidamente mediante nombres de métodos, pero también personalizarlas introduciendo consultas declaradas según sea necesario.

Creación de consultas
El mecanismo de construcción de consultas integrado en la infraestructura del repositorio de Spring Data resulta útil para construir consultas con restricciones sobre las entidades del repositorio.

El siguiente ejemplo muestra cómo crear varias consultas:

Creación de consultas a partir de nombres de métodos
interface PersonRepository extends Repository<Person, Long> {

  List<Person> findByEmailAddressAndLastname(EmailAddress emailAddress, String lastname);

  // Enables the distinct flag for the query
  List<Person> findDistinctPeopleByLastnameOrFirstname(String lastname, String firstname);
  List<Person> findPeopleDistinctByLastnameOrFirstname(String lastname, String firstname);

  // Enabling ignoring case for an individual property
  List<Person> findByLastnameIgnoreCase(String lastname);
  // Enabling ignoring case for all suitable properties
  List<Person> findByLastnameAndFirstnameAllIgnoreCase(String lastname, String firstname);

  // Enabling static ORDER BY for a query
  List<Person> findByLastnameOrderByFirstnameAsc(String lastname);
  List<Person> findByLastnameOrderByFirstnameDesc(String lastname);
}
El análisis de los nombres de los métodos de consulta se divide en sujeto y predicado. La primera parte ( find…By, exists…By) define el sujeto de la consulta, la segunda parte forma el predicado. La cláusula introductoria (sujeto) puede contener expresiones adicionales. Cualquier texto entre find(u otras palabras clave introductorias) y Byse considera descriptivo a menos que se utilice una de las palabras clave de limitación de resultados, como Distinctpara establecer una bandera distinta en la consulta que se va a crear o Top/ Firstpara limitar los resultados de la consulta .

El apéndice contiene la lista completa de palabras clave de sujeto del método de consulta y palabras clave de predicado del método de consulta, incluidos los modificadores de ordenación y mayúsculas/minúsculas . Sin embargo, el primero Byactúa como un delimitador para indicar el inicio del predicado de criterios real. A un nivel muy básico, puede definir condiciones en las propiedades de la entidad y concatenarlas con Andy Or.

El resultado real del análisis del método depende del sistema de almacenamiento persistente para el que se crea la consulta. Sin embargo, hay algunos aspectos generales a tener en cuenta:

Las expresiones suelen ser recorridos de propiedades combinados con operadores que se pueden concatenar. Puede combinar expresiones de propiedades con ANDy OR. También se admite el uso de operadores como Between, LessThan, GreaterThan, y Likepara las expresiones de propiedades. Los operadores admitidos pueden variar según el almacén de datos, por lo que debe consultar la sección correspondiente de su documentación de referencia.

El analizador de métodos admite establecer un IgnoreCaseindicador para propiedades individuales (por ejemplo, findByLastnameIgnoreCase(…)) o para todas las propiedades de un tipo que admita ignorar mayúsculas y minúsculas (normalmente Stringinstancias — por ejemplo, findByLastnameAndFirstnameAllIgnoreCase(…)). La compatibilidad con la omisión de mayúsculas y minúsculas puede variar según el almacén, por lo que se recomienda consultar las secciones pertinentes de la documentación de referencia del método de consulta específico del almacén.

Puede aplicar un ordenamiento estático agregando una OrderBycláusula al método de consulta que haga referencia a una propiedad y proporcionando una dirección de ordenamiento ( Asco Desc). Para crear un método de consulta que admita ordenamiento dinámico, consulte “ Paginación, iteración de resultados grandes, ordenamiento y limitación ”.

Expresiones de propiedad
Las expresiones de propiedad solo pueden hacer referencia a una propiedad directa de la entidad administrada, como se muestra en el ejemplo anterior. Al crear la consulta, ya se garantiza que la propiedad analizada sea una propiedad de la clase de dominio administrada. Sin embargo, también se pueden definir restricciones recorriendo propiedades anidadas. Considere la siguiente firma de método:

List<Person> findByAddressZipCode(ZipCode zipCode);
Supongamos que Persontiene un Addresscon un ZipCode. En ese caso, el método crea el x.address.zipCoderecorrido de propiedades. El algoritmo de resolución comienza interpretando toda la parte ( AddressZipCode) como la propiedad y verifica la clase de dominio para una propiedad con ese nombre (sin mayúscula). Si el algoritmo tiene éxito, usa esa propiedad. Si no, el algoritmo divide la fuente en las partes camel case del lado derecho en una cabeza y una cola e intenta encontrar la propiedad correspondiente — en nuestro ejemplo, AddressZipy Code. Si el algoritmo encuentra una propiedad con esa cabeza, toma la cola y continúa construyendo el árbol hacia abajo desde allí, dividiendo la cola hacia arriba de la manera que se acaba de describir. Si la primera división no coincide, el algoritmo mueve el punto de división a la izquierda ( Address, ZipCode) y continúa.

Aunque esto debería funcionar en la mayoría de los casos, es posible que el algoritmo seleccione la propiedad incorrecta. Supongamos que la Personclase addressZiptambién tiene una propiedad. El algoritmo coincidiría en la primera ronda de división, elegiría la propiedad incorrecta y fallaría (ya que el tipo addressZipprobablemente no tiene ninguna codepropiedad).

Para resolver esta ambigüedad, puede usar _dentro del nombre de su método para definir manualmente los puntos de recorrido. Por lo tanto, el nombre de nuestro método sería el siguiente:

List<Person> findByAddress_ZipCode(ZipCode zipCode);
Dado que tratamos los guiones bajos ( _) como un carácter reservado, recomendamos encarecidamente seguir las convenciones de nomenclatura estándar de Java (es decir, no usar guiones bajos en los nombres de las propiedades, sino aplicar la notación camel case).

Nombres de campos que comienzan con guion bajo:
Los nombres de los campos pueden comenzar con guiones bajos como String _name. Asegúrese de conservar el _como en _namey use doble _para dividir rutas anidadas como user__name.

Nombres de campos en mayúsculas:
Los nombres de campo que estén todos en mayúsculas se pueden usar como tales. Las rutas anidadas, si corresponde, requieren división mediante _como en USER_name.

Nombres de campos con la segunda letra en mayúscula:
Los nombres de campo que constan de una letra minúscula inicial seguida de una mayúscula, como String qCodese puede resolver comenzando con dos letras mayúsculas, como en QCode. Tenga en cuenta las posibles ambigüedades en la ruta.

Ambigüedades de ruta:
En el siguiente ejemplo, la disposición de las propiedades qCodey q, que qcontiene una propiedad llamada code, crea una ambigüedad para la ruta QCode.

record Container(String qCode, Code q) {}
record Code(String code) {}
Dado que se considera primero una coincidencia directa en una propiedad, no se tendrán en cuenta las posibles rutas anidadas y el algoritmo selecciona el qCodecampo. Para seleccionar el codecampo, se requiere qla notación de guion bajo .Q_Code

Limitar los resultados de la consulta
Además de la paginación, es posible limitar el tamaño del resultado mediante un Limitparámetro específico. También puede limitar los resultados de los métodos de consulta utilizando las palabras clave First`or` Top, que puede usar indistintamente, pero no debe combinarse con un Limitparámetro. Puede agregar un valor numérico opcional a Top`or` Firstpara especificar el tamaño máximo del resultado que se devolverá. Si se omite el número, se asume un tamaño de resultado de 1. El siguiente ejemplo muestra cómo limitar el tamaño de la consulta:

Limitar el tamaño del resultado de una consulta con TopyFirst
List<User> findByLastname(String lastname, Limit limit);

User findFirstByOrderByLastnameAsc();

User findTopByLastnameOrderByAgeDesc(String lastname);

Page<User> queryFirst10ByLastname(String lastname, Pageable pageable);

Slice<User> findTop3By(Pageable pageable);

List<User> findFirst10ByLastname(String lastname, Sort sort);

List<User> findTop10ByLastname(String lastname, Pageable pageable);
Las expresiones de limitación también admiten la palabra clave para almacenes de datos que admiten consultas distintas. Además, para las consultas que limitan el conjunto de resultados a una sola instancia, se admite Distinctencapsular el resultado con la palabra clave.Optional

Si se aplica paginación o segmentación a una paginación de consulta limitante (y al cálculo del número de páginas disponibles), se aplica dentro del resultado limitado.

Limitar los resultados en combinación con la ordenación dinámica mediante el uso de un Sortparámetro permite expresar métodos de consulta tanto para los 'K' elementos más pequeños como para los 'K' elementos más grandes.
